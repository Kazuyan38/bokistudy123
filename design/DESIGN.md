# BokiStudy 設計書（単一情報源）

日商簿記2級合格を目標とする、アプリ完結型学習システム。
本書はスキーマ・数値基準・運用ルールの**正本**。アプリ改修・コンテンツ追加は必ず本書に準拠すること。

- 対象ユーザー: 簿記未学習の初心者1名（3級は受験せずアプリ内卒業判定で代替、2級はCBT受験）
- 公開: GitHub Pages（`docs/` 直下、`https://kazuyan38.github.io/bokistudy123/`）
- 技術: ビルド不要の vanilla HTML/CSS/JS。外部JSライブラリ・npm禁止（Google Fontsのみ許可）
- Claudeの役割: ①アプリ開発・改善 ②コンテンツ作成 ③質問対応（学習進行の管理はアプリの学習エンジンが行う）

## 1. 学習エンジン（学習科学ベース）

### 1.1 設計原則と理論的根拠

| 設計要素 | 根拠理論 | 実装 |
|---|---|---|
| レッスン直後の小テスト必須 | テスト効果（retrieval practice） | 全セクション直後にチェックポイント2〜4問。読むだけでは先に進めない |
| アウトプット比率 約75% | テスト効果・生成効果 | 標準メニュー: 復習15分＋新レッスン5〜8分＋ドリル10分 |
| 「今日の復習」最優先提示 | エビングハウスの忘却曲線・間隔反復 | ホーム最上部に期日到来カード。SM-2ライト（§1.2） |
| 復習で単元を混ぜる | 交互練習（interleaving） | 復習・ミックスドリルは全単元横断シャッフル（同一単元は最大2連続） |
| 単元テスト80%でアンロック | 完全習得学習（mastery learning） | ソフトゲート。スキップテスト・24時間後の類題再テストで緩和 |
| 全問即時採点＋解説 | 即時フィードバック | 誤答は同セッション内で再出題（10分後扱い） |
| 例題の段階的フェード | 認知負荷理論・example fading | 完全例(worked)→一部空欄(partial)→自力(full)の3段階 |
| 仕訳は選択でなく構築 | 望ましい困難（desirable difficulties） | 科目パネルから選択＋金額テンキー入力（4択にしない） |
| 図解併用 | 二重符号化（dual coding） | 図解DSL（§4.5）をHTML/CSSで描画 |
| ダッシュボード・弱点可視化 | メタ認知・自己調整学習 | 論点カバレッジマップ・弱点タグランキング（§1.5） |
| ストリーク・1日目標 | 習慣形成・目標勾配効果 | ポイント・ランキング等の過剰な外的報酬は導入しない |

### 1.2 間隔反復アルゴリズム「SM-2ライト」

SRS対象は各単元の**コアカード**（問題JSONの `srs: true`、単元あたり8〜15問）のみ。レッスン完了時に自動投入。

カード状態: `{ ef: 2.5, ivl: 0, reps: 0, lapses: 0, due: "YYYY-MM-DD" }`

| 評価 | 条件 | 次回間隔 | EF変化 |
|---|---|---|---|
| again | 不正解 | セッション内で再出題 → 翌日(ivl=1)、reps=0、lapses+1 | ef = max(1.3, ef−0.2) |
| good | 正解 | reps=1→1日、reps=2→3日、reps≥3→round(ivl×ef) | 変化なし |
| easy | 正解＋「かんたん」押下 | round(ivl×ef×1.3) | ef = min(2.8, ef+0.05) |

- 間隔上限45日。試験日設定時は `min(45, 試験日−今日−3日)` にキャップ
- 期日超過の優先順: 超過日数降順 → lapses降順
- 1日の復習上限50枚・新規投入上限20枚（超過は翌日繰越、ホームに繰越数表示）

### 1.3 1日の標準フロー（ホームが提示する導線）

① 今日の復習（期日到来カード）→ ② 続きのレッスン（次の未完了セクション＋チェックポイント）→ ③ 今日のドリル（弱点論点優先ミックス10問）→ 完了演出＋ストリーク加算。合計25〜30分/周。1日3時間の場合は複数周＋追加ドリル。

### 1.4 習熟基準（数値）

| 判定 | 基準 |
|---|---|
| チェックポイント | 合否なし（全問解答＋解説閲覧で完了） |
| 単元合格（次単元アンロック） | 単元テスト10問中 **80%以上** |
| スキップテスト | 単元テストと同基準・別問題プール。合格で単元スキップ可 |
| 不合格時 | 24時間後に別抽出の類題で再テスト。その間、誤答論点ドリルを推奨提示 |
| Stage修了 | 全単元合格＋Stage修了テスト（全単元ミックス25問）**80%以上** |
| 3級卒業判定 | 3級CBT形式模試（60分・100点）**85点以上**（本試験合格ライン70点より厳格。受験しないため） |
| 2級受験GO判定 | 2級CBT形式模試 直近3回すべて75点以上かつ平均80点以上、かつ第1問16/20以上、第4・5問合計28/40以上、かつSRS期日超過0枚 |

### 1.5 網羅性の担保

- **論点タグ体系**: `docs/data/topics.json` に日商出題区分表を細分化した論点マスタを置き、全問題・全レッスンセクションに論点タグ必須付与
- **パターン網羅ルール**: 各論点は「基本形＋主要バリエーション全て」を出題（§7のパターン表と照合して作問）
- **カバレッジマップ**: 分析画面に論点×習熟ヒートマップ（未演習/低正答/習得済み）。弱点ドリルは未演習・低正答論点を自動優先
- **問題量目標**: Stage1 約450問／Stage2 約550問／Stage3 約400問／模試12回 約240問＝計1,600問以上
- 単元テスト・スキップテストは毎回別抽出（シャッフル＋ランダムサンプル）で暗記突破を防止

## 3. コンテンツ執筆規約

- 文体: です・ます調。専門用語は初出時に必ず定義
- 1セクション本文300〜600字（読了1〜2分）。超えるなら分割
- 例示金額は暗算しやすい数値（1,000円単位中心）
- 例示企業は架空名で統一（例: ハルカ商事、ミナト製作所、アオイ物産）
- **著作権**: 市販教材・日商過去問・予想問題集の転載/改変転載は禁止。論点名・出題区分（公表情報）の利用は可。問題文・数値・社名は完全オリジナル
- 出題区分は年度改定があるため、コンテンツ追加時に最新の区分表を確認

## 4. データスキーマ

ID規則: 問題 `q-{unitId}-{連番3桁}`／模試 `mock-{級}{連番2桁}`／論点 `t-{slug}`／セクション `{unitId}-sec{n}`。
全ファイル共通で `"schemaVersion": 1` を持つ。

### 4.1 curriculum.json（目次・前提関係）

```json
{
  "schemaVersion": 1,
  "stages": [
    {
      "id": 1, "title": "3級範囲（商業簿記の基礎）",
      "units": [
        { "id": "s1-u01", "title": "簿記の基礎", "prereq": [],
          "estMinutes": 60, "status": "available" },
        { "id": "s1-u04", "title": "手形・電子記録債権", "prereq": ["s1-u03"],
          "estMinutes": 50, "status": "planned" }
      ]
    }
  ]
}
```

- `status`: `available`（コンテンツあり）| `planned`（未作成。マップに表示するが開けない）
- コンテンツファイルは `data/lessons/{unitId}.json` と `data/questions/{unitId}.json` に必ず対で置く

### 4.2 accounts.json（勘定科目マスタ）

```json
{
  "schemaVersion": 1,
  "accounts": [
    { "id": "cash", "name": "現金", "cat": "asset", "grade": 3, "introducedIn": "s1-u01" },
    { "id": "kashidaore_hikiate", "name": "貸倒引当金", "cat": "asset", "grade": 3, "introducedIn": "s1-u07", "contra": true }
  ]
}
```

- `cat`: `asset | liability | equity | revenue | expense | other`
- `contra: true` は評価勘定（貸倒引当金・減価償却累計額）。パネルでは cat のタブ内に表示
- 科目パネルは「introducedIn が学習済み単元」の科目のみ表示（進度連動）

### 4.3 topics.json（論点タグマスタ）

```json
{
  "schemaVersion": 1,
  "topics": [
    { "id": "t-goyoso", "name": "簿記の5要素", "unitId": "s1-u01" },
    { "id": "t-sanbunpo", "name": "三分法", "unitId": "s1-u02" }
  ]
}
```

### 4.4 lessons/{unitId}.json

```json
{
  "schemaVersion": 1,
  "unitId": "s1-u02",
  "title": "商品売買",
  "stage": 1,
  "estMinutes": 60,
  "sections": [
    {
      "id": "s1-u02-sec1",
      "title": "三分法とは",
      "topics": ["t-sanbunpo"],
      "blocks": [
        { "type": "text", "md": "本文300〜600字。**強調**と箇条書き（- ）のみの軽量Markdown。" },
        { "type": "figure", "figure": { "kind": "journal", "caption": "商品1,000円を掛けで仕入れた",
            "rows": [ { "dr": [["仕入", 1000]], "cr": [["買掛金", 1000]] } ] } },
        { "type": "example", "fading": "worked", "md": "**例題**: ハルカ商事は…" }
      ],
      "checkpoint": ["q-s1-u02-001", "q-s1-u02-002"]
    }
  ]
}
```

- `blocks[].type`: `text` | `figure` | `example`（`fading: worked | partial | full`）
- `md` の許可記法: `**強調**`、`- 箇条書き`、改行。それ以外は使わない（自前軽量パーサで描画）
- `checkpoint` は同単元 questions ファイル内の問題IDを参照

### 4.5 図解DSL（`figure.kind`）

| kind | 用途 | データ形 |
|---|---|---|
| `journal` | 仕訳表 | `rows: [{ dr: [[科目名, 金額]...], cr: [[科目名, 金額]...] }]` |
| `taccount` | T字勘定 | `account: "現金", left: [["摘要", 金額]...], right: [["摘要", 金額]...]` |
| `bspl` | B/S・P/Lボックス図 | `chart: "bs" or "pl", left: [["資産", 100]...], right: [["負債", 60], ["純資産", 40]]` |
| `flow` | 取引フロー・勘定連絡図 | `nodes: [{id, label}], edges: [{from, to, label}]`（CSS Grid配置） |
| `worksheet` | 精算表・試算表（v0.2〜） | `columns: [...], rows: [[...]]`（横スクロール） |
| `calcbox` | 原価計算ボックス図（v0.6〜） | 専用構造（導入時に定義） |

図解はSVGでなくHTMLテーブル＋CSSで描画（`docs/js/render/figures.js`）。

### 4.6 questions/{unitId}.json

共通フィールド: `id, type, unitId, topics[], difficulty(1-3), srs(bool), stem, explanation, lessonRef`

```json
{
  "schemaVersion": 1,
  "unitId": "s1-u02",
  "questions": [
    { "id": "q-s1-u02-001", "type": "journal", "unitId": "s1-u02",
      "topics": ["t-sanbunpo"], "difficulty": 1, "srs": true,
      "stem": "ハルカ商事は商品3,000円を仕入れ、代金は掛けとした。",
      "answer": { "dr": [{ "acc": "shiire", "amt": 3000 }],
                  "cr": [{ "acc": "kaikake", "amt": 3000 }], "alt": [] },
      "explanation": "三分法では仕入時に費用の勘定「仕入」を用います。…",
      "lessonRef": "s1-u02-sec1" },
    { "id": "q-s1-u01-002", "type": "mc", "unitId": "s1-u01",
      "topics": ["t-goyoso"], "difficulty": 1, "srs": false,
      "stem": "次のうち「負債」に分類されるものはどれですか。",
      "choices": ["売掛金", "買掛金", "資本金", "受取手数料"], "answer": 1, "shuffle": true,
      "explanation": "買掛金は将来支払う義務＝負債です。…" },
    { "id": "q-s1-u01-003", "type": "tf", "unitId": "s1-u01",
      "topics": ["t-bspl"], "difficulty": 1, "srs": false,
      "stem": "貸借対照表の借方（左側）には資産が記載される。",
      "answer": true,
      "explanation": "資産は借方、負債・純資産は貸方に記載します。" },
    { "id": "q-s1-u06-010", "type": "fill_number", "unitId": "s1-u06",
      "topics": ["t-genka-shokyaku"], "difficulty": 2, "srs": true,
      "stem": "取得原価600,000円、耐用年数5年、残存価額ゼロ、定額法。当期1年分の減価償却費はいくらですか。",
      "answer": { "value": 120000, "unit": "円" },
      "explanation": "600,000 ÷ 5年 = 120,000円です。" }
  ]
}
```

- `journal.answer`: `acc` は accounts.json の id。採点は借方/貸方それぞれ**行順不問の集合一致**。`alt` は許容別解の配列（同構造）。貸借合計不一致は即不正解＋指摘
- `mc.answer` はインデックス。`shuffle: true` で表示時シャッフル
- `fill_number`: カンマ入力許容、負数は△入力対応、`tolerance` 省略時0
- v0.2以降: `table_fill`（表内複数ブランク・部分点）、v0.4: `multi_fill`（複合小問）を追加定義する

### 4.7 mocks/{mockId}.json（模試）

```json
{
  "schemaVersion": 1, "id": "mock-201", "grade": 2,
  "timeLimitMin": 90, "passScore": 70,
  "sections": [
    { "no": 1, "label": "第1問 仕訳", "points": 20,
      "questions": [{ "qid": "qm-201-1-1", "pts": 4 }] }
  ]
}
```

2級: 90分・大問5（20/20/20/28/12点）。3級形式（卒業判定用 mock-301〜）: 60分・第1問仕訳45点/第2問20点/第3問35点。
模試UI: タイマー常時表示、大問タブ、「後で見直す」フラグ、終了時に大問別スコア・弱点論点を保存。

### 4.8 localStorage 設計

| キー | 内容 |
|---|---|
| `boki.v1.profile` | 目標試験日、1日目標（デフォルト20問、10〜60可変）、設定 |
| `boki.v1.progress` | 単元ごと `{ lessonDone: [secId], testBest, passed, passedAt }` |
| `boki.v1.srs` | カードID → `{ ef, ivl, reps, lapses, due }` |
| `boki.v1.stats` | 日別 `{ date, answered, correct, minutes }`、論点別成績、ストリーク、休息チケット（月2枚） |
| `boki.v1.mocks` | 模試結果履歴（大問別スコア） |

- 全キーに schemaVersion を含め、起動時マイグレーション関数を通す
- **バックアップ**: 設定画面から全データJSONをダウンロード/コピー。インポートは貼り付け＋確認ダイアログ。週1回のエクスポートをアプリがリマインド
- **質問用サマリー**: 設定画面の「質問用サマリーをコピー」で人間可読Markdownを生成（現在地・直近7日の解答数と正答率・単元テスト不合格履歴・弱点論点Top5・SRS状態）→ ユーザーがClaudeに貼って質問

## 5. アプリ画面・UX

### 5.1 ルーティング（ハッシュSPA）

`#home` `#map` `#lesson/{unitId}/{secIdx}` `#drill/{mode}` `#review` `#test/{unitId}` `#mock/{mockId}` `#stats` `#calc` `#settings`

下部固定ナビ5タブ: ホーム／学習（マップ）／復習／分析／設定。電卓はフローティングボタン＋`#calc`。

### 5.2 主要画面

- **ホーム**: ストリーク・進捗リング（今日の目標）／①今日の復習 n枚 ②続きのレッスン ③今日のドリル の3カード
- **学習マップ**: Stage→単元リスト。合格✓・学習中▶・ロック🔒（アンロック条件表示）・planned（今後追加）。単元→レッスン/ドリル/テスト/スキップテスト
- **ドリル**: 1問ずつ即時採点→解説→次へ。10問1セット。誤答はセッション内再出題
- **仕訳UI**: 借方/貸方の行（科目チップ＋金額）、行追加、科目パネル（カテゴリタブ＋検索、学習済み科目のみ）、画面内テンキー
- **分析**: 単元別習熟ヒートマップ、論点カバレッジマップ、弱点論点Top5、期日超過カード数、日別学習量
- **電卓**: 実務電卓を模した12桁電卓。四則・√・%・M+/M-/MR/MC・GT。ドリル・模試中はフローティングボタン→スライドアップ（問題文を隠さない高さ）。単体画面でも利用可。キー配列は一般的な実務電卓準拠（本番CBTへの操作転移）

### 5.3 デザインシステム

- **コンセプト**: 「上質な文具」。教育アプリの原色ベタ塗り感を排し、落ち着いた知的トーンで学習意欲を高める
- **カラートークン**（CSS変数 `--c-*`）:
  - ベース: 生成り `#F7F5F0`／カード白 `#FFFFFF`
  - プライマリ: 深紺 `#1B2A4A`（ヘッダ・主要ボタン）
  - アクセント: 金茶 `#C89B3C`（達成・強調）
  - インク: `#1F2433`／サブテキスト `#6B7280`
  - 正解 `#2E7D5B`／誤答 `#C0504D`（色＋アイコン併用で色覚多様性対応）
  - 借方 `#3D5A80`／貸方 `#9A6A4F`（仕訳UIの左右識別）
- **タイポグラフィ**: 見出し=Zen Kaku Gothic New（Google Fonts）／本文=システム和文スタック併用／金額=tabular-nums＋等幅
- **形状**: カード角丸16px、繊細なシャドウ（2層）、余白広め（8pxグリッド）
- **アイコン**: 手描きSVG（絵文字をUIアイコンに使わない）
- **モーション**: 正解チェックマークのポップ、進捗リングのアニメーション、画面遷移フェード、単元合格・ストリーク達成の達成演出。すべてCSSアニメーション
- **レイアウト**: 縦1カラム・最大幅640px中央寄せ。タップ最小44px。数値入力は `inputmode="numeric"`＋画面内テンキー。横長表は横スクロール＋先頭列sticky
- ダークモードはv2（トークンは最初から変数化）

### 5.4 継続の仕組み

- ストリーク: 「今日の復習完了 or 20問解答」で1日達成。休息チケット月2枚で途切れ防止
- 1日目標: デフォルト20問（設定で10〜60）
- 導入しない: ポイント・ランキング・課金的演出（内発的動機づけ優先）

## 10. リスク・留意点

- localStorage消失: 週1バックアップリマインダー＋Driveへの世代保管
- リポジトリはpublic: 個人情報は書かない。学習データはlocalStorageのみ（リポジトリに置かない）
- OneDrive配下: コミットを小まめに（同期競合対策）
- スマホでの表入力（精算表・連結）: セル単位フォーカス移動＋部分点。必要なら「横持ち推奨」注記
